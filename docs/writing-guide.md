# 読ませるページの書き方（調べたことと、このサイトの決まり）

このサイトの文章を書く・直す人のためのメモです。Web の読まれ方と、読みやすい文章について調べたことをまとめ、それをこのサイトでどう使っているかを書いています。

## 1. 調べてわかったこと

### 人は Web のページを「読まずに拾い読みする」

- ユーザビリティの研究で知られるヤコブ・ニールセンの 1997 年の調査では、利用者の 79% が新しいページを拾い読み（スキャン）し、一語ずつ読んだのは 16% だけでした。勧められていたのは、強調したキーワード、意味のある小見出し、箇条書き、一段落に一つの考え、結論を先に書く「逆ピラミッド」、ふつうの半分以下の文字量です。（[How Users Read on the Web](https://www.nngroup.com/articles/how-users-read-on-the-web/)）
- 視線の研究では、見出しと小見出しを拾い、気になったところだけ本文を読む「レイヤーケーキ型」の読み方が知られています。見出しがはっきりしていて、中身を表しているときに起きる読み方です。（[Text Scanning Patterns](https://www.nngroup.com/articles/text-scanning-patterns-eyetracking/)）
- 2018 年の調査では、ページを見ている時間のおよそ 74% が、最初の二画面に集中していました。（[Scrolling and Attention](https://www.nngroup.com/articles/scrolling-and-attention/)）

→ **見出しだけ、要点だけを拾っても話がわかるようにする。いちばん大事なことは最初の二画面に置く。**

### 結論を先に、文は短く

- 木下是雄『理科系の作文技術』（中公新書, 1981）は、大事なことを先に書く「重点先行主義」と、短い文で書くことを説いています。読む人が、続きを読むべきかをすぐ判断できるようにするためです。
- 日本語の読みやすさの研究では、文の長さと漢字の割合が大きく効くとされてきました。漢字が4〜5字以上続くと読みにくい、という目安もあります。

→ **章も段落も、結論から書く。一文に一つのことだけ。漢字が続いたら、ひらがなや言い換えで切る。**

### 問いかけと、身近な例

- 心理学者ローウェンスタインの「情報の空白」の考え方（1994）によると、好奇心は「知っていることと知りたいことの間のすき間」に気づいたときに生まれます。ただし、すき間が大きすぎても小さすぎても働かず、少しは知っていて、答えにたどり着けそうなときに強くなります。
- 抽象的な考えは、具体的な例と一緒に学ぶと理解しやすく、新しい場面にも当てはめやすくなることが、学習の研究で確かめられています（Rawson ほか, 2015 など）。

→ **問いかけは、読者が知っている身近なことについて聞き、すぐ後で答える。抽象的な話の前に、具体的な例を一つ置く。**

### 文字の組み方

- アクセシビリティの国際基準 WCAG 2.2 の達成基準 1.4.8（AAA）は、一行の長さを 80 字以内（日本語などは 40 字以内）、行間を 1.5 倍以上、段落の間をそれ以上にすることを挙げています。両端そろえも避けるよう書かれています。（[Understanding SC 1.4.8](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation)）

→ **本文は一行 36 字前後、行間は 2 倍前後にしている（`src/styles/global.css` の `.longform`）。**

## 2. このサイトの決まり

### ページの組み立て

1. **最初に、まとめを置く。** トップページの「3分で読むなら」は、各章の見出しと要点から自動で作られます。
2. **章は「問い → 主張 → 要点 → 本文」の順。** 章の上の小さな文字（eyebrow）は読者が心の中で持っている問い、見出しはそれに答える主張、すぐ下に要点を置きます。
3. **見出しは主張の形で書く。** 「データ分析について」ではなく「数字は同じでも、形はまったく違う」。見出しを上から読むだけで、話がつながるようにします。
4. **大事さに合わせて見た目を変える。**

   | ブロック               | いつ使うか                                                                 | 見た目                           |
   | ---------------------- | -------------------------------------------------------------------------- | -------------------------------- |
   | `point`（要点）        | その部分でいちばん言いたいこと。拾い読みする人はここだけ読む               | オレンジの線                     |
   | `question`（問いかけ） | 身近なことを聞いて、続きを読みたくさせる。答えは `answer` に               | 「？」の印                       |
   | `example`（身近な例）  | 抽象的な話の前後に、具体的な場面を一つ                                     | 灰色の箱                         |
   | `heading`（小見出し）  | 章の中で話が切り替わるところ                                               | 黒い四角                         |
   | `aside`（補足）        | 読み飛ばしても本筋がわかること（数字の出どころ、細かい事情、歴史の寄り道） | 折りたたみ・「読み飛ばしてもOK」 |
   | `p`（段落）            | 本文。一段落に一つの考え                                                   | —                                |

5. **トップページに、人名や出典を並べない。** 必要なら `aside` に入れる。詳しい出典は「設計を知る」のページの注と参考文献に書く。

### 文の書き方

- 一文は短く。読点（、）で三つ以上つながったら、文を分ける。
- 専門用語は、初めて出てきたところで言い換える（例：「要件（設計が満たすべき条件）」）。
- 「〜と言われています」は、出どころがはっきりしない数字に使う。確かめた数字は言い切る。
- 強調（`**…**`）は一段落に一か所まで。多すぎると、どこも目立たなくなる。
- 身近な例は、読者（大学生）の生活から選ぶ。授業の課題、サークル、アルバイト、家の中のもの。業界の話は補足に回す。
- 同じ言葉（「価値」「考え抜く」など）を何度も使わない。決め台詞は、ここぞという一か所だけにする。
- 問いかけの答えは、すぐ後に書く。拾い読みする人にも見せたい答えは `open: true` で最初から開いておく。
- 読者を突き放す言い方をしない。たとえば「センスではなく論理」は、デザインを学ぶ人には「センスは要らない」と読める。「センスだけでなく」と書く。

### 「設計を知る」のページ

- 決まった章立てはありません。そのテーマが**いちばん伝わる順番**で書きます。多くのページは「身近な問い → 何なのか → なぜ大事か → どう使うか → いま → 設計会では → 寄り道（歴史）」の順ですが、合わなければ変えてかまいません。
- 新しいテーマは、`src/content/design/` に YAML を一つ足すだけで、一覧・地図・リンクに加わります。
  - 設計の工程を説明するもの … `layer: process`（いまは「設計のプロセス」の一ページだけ）
  - どの工程にも通じる視点 … `layer: lens`。`perStep` を書くと、地図の表に「工程ごとの使い方」が出る（書かなければ空欄）
  - それ以外のテーマ … `layer: topic`
